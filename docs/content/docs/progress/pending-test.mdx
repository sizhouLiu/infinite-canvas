# Pending Tests

The current release needs manual verification in these areas:

- Tripo 3D generation: the channel editor should offer "Tripo" as an apiFormat, filling the base URL with `https://openapi.tripo3d.com`; the capability list should include "3D", and the model list should offer `v3.1-20260211`, `v3.0-20250812`, `v2.5-20250123`, `P1-20260311`, and `P2-20260801` directly (Tripo has no model-list endpoint, so no `/v1/models` request should be made). After saving the channel and reloading the page, its apiFormat must still be Tripo rather than OpenAI. Preferences should show a default 3D model.
- Tripo 3D generation flow: Tripo's `/v3` endpoints send no CORS headers, so the local proxy must be enabled; with it off, generation should report a readable error instead of failing silently. The configuration node's mode selector should include "3D", and both the text prompt panel and the 3D node prompt panel should show the 3D model picker and 3D settings. A prompt alone runs text-to-3D; an upstream image node uploads the image first and runs image-to-3D. While generating, the node shows a progress placeholder; on success it should show a model that rotates by dragging and zooms by scrolling (three.js loads from a CDN on demand, so a network connection is required), with the preview image shown first as a placeholder. Measured: text-to-3D about 3 minutes and 10–30 credits, image-to-3D about 80 seconds and 20 credits.
- Tripo 3D settings: the 3D settings panel should offer texture, PBR material, texture quality (standard/detailed/extreme), and a face limit. An empty face limit means auto; a value outside the model's range should surface Tripo's own message verbatim (ranges differ per model, e.g. 48–50000 for P2) rather than being blocked client-side. Changes are recorded on the node, and regenerating reuses that node's settings.
- Tripo 3D persistence and resume: reloading mid-generation should resume polling from the stored task id instead of turning the node into an error; only a terminal Tripo failure clears the task id, while a timeout or network failure keeps it retryable. After a successful generation, closing and reopening the canvas should read the model and preview back from local storage (Tripo's signed URLs expire within a day, so the remote URL must not be relied on), and this should still work with the local proxy switched off. Right-clicking a 3D node should download a `.glb`. Placing more than three 3D nodes and repeatedly deleting and recreating them should not blank the canvas or exhaust WebGL contexts.
- Tripo image generation: a Tripo channel's model list should also offer the image models `seedream_v5`, `seedream_v4`, `banana`, `banana_pro`, `banana2`, `chat_image_2`, `chat_image_2.5_flare`, `chat_image_2.5_sunburst`, `chat_image_1.5`, and `chat_image_1`, each classified as an image capability rather than 3D. A prompt alone runs text-to-image; connecting reference image nodes uploads each one and runs image-to-image. Tripo has no `n` parameter, so requesting several images issues several tasks and each is billed separately. Results should be fetched from the CDN and stored locally like other image generations — image outputs come from a CloudFront host that sends no CORS headers (unlike the 3D output CDN), so that download goes through the local proxy as well and should not raise a fetch error in the console. Image generation goes through the same `/v3` endpoints as 3D, so it needs the local proxy too; with the proxy off, both should fail immediately with a message telling you to enable it rather than only logging CORS errors to the console.
- Tripo image sizing per model: each family accepts different size arguments, so the request should adapt instead of failing. `seedream_v4` accepts only the 2K and 4K tiers and `seedream_v5` only 2K and 3K, so a 1K or 4K canvas setting should snap to the nearest accepted tier rather than returning a 1004. `banana` and `banana_pro` accept only a fixed pixel list (`1024x1024`, `832x1248`, and so on) and otherwise fall back to `aspect_ratio`. `banana2` takes a K-tier plus `aspect_ratio`. The `chat_image` models take an explicit WxH or the literal `auto`, never a K-tier, and only `chat_image_2`, `chat_image_2.5_flare`, and `chat_image_2.5_sunburst` accept `quality` (sending it to any other model is a hard 1004); `background` applies only to the two 2.5 models.
- Tripo regions: two channels should ship by default, one for the China region (`https://openapi.tripo3d.com`) and one for the global region (`https://openapi.tripo3d.ai`), each pre-populated with `v3.1-20260211` and `seedream_v5`. With apiFormat set to Tripo, the channel editor should show a region picker that rewrites the base URL, and it should be hidden for other formats. The two regions are separate accounts, so each channel keeps its own API key and a key from one region should not authenticate against the other; both regions need the local proxy.
- 3D node double-click to enlarge: double-clicking a 3D node that holds a model should open a large viewer (80vw wide, 72vh tall) titled with the node name, where dragging to orbit and scrolling to zoom work without first switching the node to interact mode. The double-click should work whether the node is in move or interact mode. An empty 3D node should not open anything; image nodes should still open the image preview, text nodes should still enter editing, and double-clicking empty canvas should still open the create menu. Opening and closing several 3D viewers repeatedly should not blank the canvas or exhaust WebGL contexts (the modal uses destroyOnHidden so the context is released on close).
- Tripo readable auth errors: with a wrong API key, or a China-region key saved on the global-region channel (the two regions are separate accounts — verified: the same key works on `.com` and returns "Invalid API key" on `.ai`), image generation, 3D generation, reference-image upload, and every 3D operation should report an authentication failure that explains keys are not shared across regions, instead of only "Request failed with status code 401" that forces you into the network tab. With the proxy toggle on but the command not running, the error should say the local proxy is unreachable. Task-level failures (content policy, timeout) and cancellation messages should be unchanged.
- Tripo 3D topology: the 3D settings panel should show a "Topology" row (Triangles / Quads) when P2, v3.0, or v3.1 is selected, and hide it for P1 and v2.5 — P1 rejects the field outright (verified: "quad is only supported by model P2-20260801"), so it is not sent for unsupported models. Choosing Quads should show a note that on the H series (v3.x) the output becomes FBX and cannot be previewed on the canvas, only downloaded (worth confirming with a real generation), and that P2's face limit drops to 48–25,000 — exceeding it should surface Tripo's own message. The setting is stored on the node and reused when regenerating.
- Tripo image-to-3D auth: with a Tripo API key configured on the channel (image generation already working), image-to-3D, multiview-to-3D, and image-to-multiview should no longer report "Configure the API key first" — the reference-image upload step was not resolving the model's channel and read the empty top-level apiKey. Worth checking with several channels configured (e.g. OpenAI first, Tripo later in the list).
- Tripo optional 3D prompt: with images connected to a 3D node, the generate button should work with an empty prompt (image-to-3D and multiview-to-3D need no prompt, and Tripo does not accept one), and the placeholder should say a prompt is optional. With no images connected the prompt is still required (text-to-3D) and the button stays disabled. Text, image, video, and audio modes are unchanged — an empty prompt still cannot generate. Also, the 3D prompt box previously had no placeholder text at all and rendered the raw translation key; it should now show real text in both languages.
- Tripo multiview to 3D: connecting 2–4 image nodes to a 3D generation should run multiview-to-model instead of using only the first image. The front view is required, so the first connected image becomes the front unless that node came from a multiview run (in which case its own angle is used). Connecting more than 4 images should warn that only the first 4 were used, rather than silently dropping the rest. A single image should still run image-to-3D and a prompt alone text-to-3D.
- Tripo multiview images: an image node's toolbar has a "Multiview" tool (off by default — it spends credits, unlike the local image tools; enable it via the toolbar's "more" settings). On a plain image it generates four views, which land as four image nodes in a 2x2 grid to the right, each connected to the source and labelled front/left/back/right. Running the tool on one of those generated view nodes should instead open the edit dialog, where filling in only some views edits just those. Editing requires the original multiview task, so it only works on nodes produced by a multiview run in this canvas.
- Tripo 3D operations menu: hovering a 3D node that holds a model shows a "3D ops" menu with retexture, auto-rig, apply animation, decimate, segment parts, complete mesh, and convert format. Each operation opens one shared parameter dialog whose fields differ per operation. Every operation except conversion should create a new 3D node to the right of the source, connected to it, and store its own task id so the chain can continue.
- Tripo operation chaining limits: "Apply animation" must be greyed out with an explanation on any node that was not rigged in this canvas, and "Complete mesh" likewise on any node that was not segmented here — Tripo only accepts the upstream task id for these two and rejects an uploaded file. On nodes that do qualify, both should run. Every other operation should work on any 3D node, including one restored after reopening the project (it re-uploads the stored model to get a token when the task id is gone).
- Tripo auto-rig pre-check: rigging first runs the free rig-check. For a model Tripo reports as non-riggable, generation should stop with a readable message naming the detected type and consume no credits. Note the rig model enums differ from the generation models, and only some rig types have preset animations, so the animation list is empty for those.

GLB is not offered because Tripo rejects it. After a conversion, closing and reopening the project should keep the download working — the converted blob must survive the unused-media sweep. Refreshing mid-conversion should resume the task rather than losing it, since conversions are billed.

## 图片分辨率尺寸表

选择分辨率和宽高比后，W/H 按下表填写，单位为像素。预设尺寸不受「16 倍数对齐」开关影响；该开关只控制手动输入尺寸时的对齐。最终生成尺寸以所选模型的实际输出为准。

| 宽高比 | 1K | 2K | 4K |
| --- | ---: | ---: | ---: |
| **1:1** | **1024 × 1024** | **2048 × 2048** | **2880 × 2880** |
| **2:3** | 1024 × 1536 | 1360 × 2048 | 2336 × 3520 |
| **3:2** | 1536 × 1024 | 2048 × 1360 | 3520 × 2336 |
| **4:3** | 1024 × 768 | 2048 × 1536 | 3312 × 2480 |
| **3:4** | 768 × 1024 | 1536 × 2048 | 2480 × 3312 |
| **16:9** | 1536 × 864 | 2048 × 1152 | **3840 × 2160** |
| **9:16** | 864 × 1536 | 1152 × 2048 | **2160 × 3840** |
| **21:9** | 2016 × 864 | 2688 × 1152 | **3840 × 1648** |
| **9:21** | 864 × 2016 | 1152 × 2688 | **1648 × 3840** |

待验收：

- 在画布和图像工作台逐项切换 3 档分辨率与 9 种比例，W/H 应与表格一致，重新打开设置后仍选中正确档位；重点检查 1K 的 2:3、16:9、21:9 及对应竖图，以及 4K 的 1:1。
- 所有 4K 预设提交时均不应触发本地总像素或最长边限制；生成和编辑请求、调用脚本应收到所选像素尺寸。
- 分辨率为自动时保留比例选择，比例为自动时禁用 W/H；手动输入 W/H 后，对齐开关仍应按原有方式工作。
- Gemini 在质量为自动时，应将表中尺寸识别为对应的 1K / 2K / 4K；显式选择质量时维持原有优先级。视频尺寸设置应保持原有行为。
